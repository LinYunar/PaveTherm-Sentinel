# 飞书卡片排版架构 (V1 / V2)

**2026-06-30 晚新增** — 用户反馈 V1 批量卡片"信息挤一团没有分割,看起来太累", 新加 V2。

## 双版本并存设计

**为什么不直接替换 V1?**

- 留退路: V1 字段映射是约定, 改 V1 怕破坏老调用方
- 切换成本低: `push_batch(version="v2")` 一参数
- V1 适合少点数 (1-3 点) 对比场景, V2 适合 6+ 点罗列

```
feishu_push.py::push_batch(chat_id, results, use_card=True, version="v2")
├── version="v1" → alert.render_multi_point_card()
│                  └─ column_set 2 列网格, 6-8 行/点, 紧凑
└── version="v2" → alert.render_multi_point_card_v2()
                   └─ 分块+全展开+树形字段+双等级, 清新
```

## V1 vs V2 对比

| 项 | V1 (旧) | V2 (新, 默认) |
|---|---|---|
| 6 点排版 | 2 列 `column_set` 网格 | 每点独立 `div` + `hr` 分割 |
| 字段组织 | 一行堆到底 (路表 41.5°C · 气温 26.7°C) | 树形 `├` `└` 逐行展示 |
| 点与点之间 | column 边界 (无明显分隔) | `hr` 分割线 |
| 等级显示 | 只显示当前 | **当前 + 14 天峰值** 双等级 |
| 区块结构 | 单一长流 | 4 大区块 (摘要 / 最危险日 / 详情 / footer) |
| 字符预算 | 6 点 ~2800 | 6 点 ~3166 (上限 4096) |
| 移动端读 | 字号小, 信息挤 | 清晰, 一目了然 |

## V2 关键设计原则 (新卡片前必读)

1. **每点独立 div** — 不用 column 网格。column 适合 1-3 点对比, 不适合 6+ 点罗列
2. **每点内字段树形化** — `├` `└` 表示层级, 不要用空格缩进 (飞书 markdown 不渲染缩进)
3. **双等级显示** — 当前温度等级 + 14 天峰值等级都要显示, 避免"现在绿+未来红"被掩盖
4. **预算 3500 字符** — 超了拆卡 (按等级分组 / 按维度拆分), 不要裁剪字段
5. **全展开** — 不要用 `collapsible_panel` 隐藏细节 (用户说"我不要点开看, 一眼就要看到所有信息")

## 排版决策表 (按点数)

| 点数 | 推荐排版 | 字符预算 |
|---|---|---|
| 1 | 单点卡片 (已有) | 2000 字符 |
| 2-3 | V1 (column_set 2 列) | 2000 字符 |
| 4-6 | V2 (分块+树形) | 3500 字符 |
| 7-10 | V2 + 头部精简 (去掉 "整页摘要" 区块) | 4000 字符 |
| 10+ | **拆 3 张卡片** (按等级分组) | 每张 3500 |

## V2 已知边界 (2026-06-30)

- 6 点全绿样本下, 头部 header 是绿色, 但 14 天内有红警 — 头部颜色**没按 14 天峰值**判, 是按当前等级。可改进: header template 也按 14 天峰值判
- `peak_14d_max_date` 6 个点都显示 2026-07-13 (因为都是同一日最热) — 但每个点的 "14 天峰值" 是它自己的最高温日, 巧合都在 7-13。**没 bug**, 但显示一样会引起"是不是 bug"的疑问
- 移动端 column_set 限制: V2 不用 column_set, 避免此问题
- 颜色"绿色"但内容含"红警" — header 颜色是误导, 改进方向: 头部颜色按 14 天峰值判
